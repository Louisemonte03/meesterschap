Leerdoelen

Eerste leerdoelen

  1. 01

    Externe data ophalen en verwerken via een API

    Mijn websites zijn tot nu toe vooral statisch opgebouwd. Ik wil leren hoe ik via JavaScript een externe API kan aanroepen, de data ophaal en die dynamisch op een pagina toon, zodat de content niet hardcoded is maar uit een echte bron komt.

    Dit doel is geslaagd als ik een werkende fetch-aanroep heb gebouwd, de response verwerk en zinvol weergeef in de interface, zonder een tutorial te volgen maar op basis van eigen begrip.

  2. 02

    Beweging toevoegen met CSS zonder JavaScript

    Animaties gebruik ik nu bijna niet, of ik grijp meteen naar JavaScript. Ik wil leren hoe ik met puur CSS, via keyframes en scroll-driven animations, subtiele beweging toevoeg die de beleving van een pagina versterkt.

    Dit doel is geslaagd als ik aantoonbaar animaties heb gebouwd die reageren op scroll of interactie, alleen met CSS, en die bijdragen aan de sfeer van de pagina in plaats van afleiden.

  3. 03

    Een interface bouwen die er verzorgd uitziet

    Ik merk dat mijn ontwerpen technisch kloppen maar visueel soms onrustig of onaf aanvoelen. Ik wil bewuster omgaan met typografie, witruimte en visuele balans, zodat een pagina meteen rustig en doordacht oogt.

    Dit doel is geslaagd als ik een project kan opleveren waarbij de visuele keuzes zoals lettergrootte, spacing en kleur bewust zijn gemaakt en als geheel kloppen.

Reflectie op leerdoelen Sprint 0

Als ik mezelf vergelijk met hoe ik code schreef in het begin van CMD en nu, kan ik zeggen dat ik met stijgende lijn ben gegroeid. Ik merk dat ik een oog voor detail heb en clean interfaces maak, dat was in het begin echt niet zo. Als inspiratie zocht ik altijd Apple op omdat ik hun interfaces clean vind. Dat doel heb ik behaald.

Bij het vak Project Tech werkten we in groepjes met API's. Ik begreep er vrij weinig van, maar het was een leuke ervaring. Toen ik mijn leerdoel moest schrijven was dat dan ook het eerste wat me te binnen schoot. Bij het vak API heb ik mijn leerdoel zeker overtroffen, met een 8,5 en veel vragen aan Jad en Syd om alles goed te begrijpen.

Hoewel ik al clean designs kon maken, wilde ik de interface verder verbeteren met subtiele animaties om de beleving te verfijnen. Ik merkte dat ik dit niet echt heb toegepast zoals ik wilde. Dat kon beter, dus ik neem dit leerdoel mee naar de meesterproef.

Tweede leerdoelen

  1. 04

    Leiderschap loslaten en samenwerken

    Ik merk dat ik de neiging heb om alles zelf te willen doen, uit het gevoel dat ik dan betere controle heb over het eindresultaat. Dit staat samenwerking in de weg en legt onnodig veel druk bij mezelf. Ik wil leren om taken los te laten, vertrouwen te hebben in anderen en mijn energie te richten op mijn eigen bijdrage in plaats van het geheel te willen overzien.

    Dit doel is geslaagd als ik in een groepsproject aantoonbaar taken heb verdeeld, ruimte heb gegeven aan de aanpak van anderen en achteraf kan reflecteren op wat dat heeft opgeleverd.

  2. 05

    Beweging toevoegen met CSS zonder JavaScript

  3. 06

    Samenwerken met Git branches

    Ik werk op dit moment voornamelijk op één branch en gebruik Git vooral om mijn eigen voortgang op te slaan. Ik wil leren hoe je met branches werkt in een team: feature branches aanmaken, pull requests openen en merge conflicts oplossen zonder dat het project in de war raakt.

    Dit doel is geslaagd als ik in een samenwerkingsproject meerdere branches heb gebruikt, een pull request heb aangemaakt en beoordeeld, en een merge conflict zelfstandig heb opgelost.

Reflectie op leerdoelen Meesterproef

Leiderschap loslaten en samenwerken
Tijdens de hackathon was ik te veel bezig met organiseren en steeds vragen om duidelijke communicatie, waardoor ik me niet goed kon focussen. Ik merkte dat ik de neiging had om alles zelf te doen. Dit leerdoel heb ik zeker behaald en ik ben er tevreden mee. De meesterproef was een hele goede ervaring: goede samenwerking, duidelijke planning, structuur en communicatie.

Samenwerken met Git branches
Na de hackathon, waar het regelmatig misging met branches, wist ik dat ik dit beter onder de knie wilde hebben. Git gaf me een soort angst: dingen kunnen worden overschreven of stuk gaan terwijl iemand er lang aan heeft gewerkt. Maar tijdens de meesterproef heb ik mezelf overtroffen. Ik nam rustig de tijd om errors en conflicts te lezen en was over het algemeen degene die de git beheerde. Veel is goed gegaan, een paar kleine foutjes heb ik kunnen oplossen.

Animaties
Dit is het enige leerdoel waarop ik denk dat ik tekort ben geschoten. Ik heb maar een paar kleine animaties toegevoegd. Onze opdrachtgever hamerde elke keer op animaties, terwijl we nog bij het eerste prototype waren. We moesten hem er steeds op attenderen dat een werkend prototype eerst prioriteit heeft en dat animaties er later bij komen. Ik vond het zelf lastig om dat aan te geven, en ook lastig om te zoeken naar de juiste animaties voor een mobiele app — daarin heb ik mijn creativiteit onvoldoende ingezet.
