Reflectie

Sprint 0

Bij sprint 0 begon ik zonder enig idee. Als eerst begon ik met een idee om de spotify api te gebruiken. Maar ik merkte dat dat misschien te groot was om na te maken voor zo'n korte peroiode Ik moest beginnen met het maken van iets persoonlijks. Wat echt bij mij hoort. Ik had iets sport gerelateerd gemaakt. Ik hou van sporten en dat heb ik in de stijl van mijn favorite voetbalclub gedaan. Daarvan heb ik de huistijl van aangehouden en in mijn website geimplementeerd. We moesten de leerdoelen contreet op schrijven. Ik had dat nog niet gedaan. Maar bij het herkansings vak voor sprint 0 heb ik dat beter verwoord en wat ik nou eigenlijk wil leren en ook waarom. Uiteindelijk ben ik overgestapt op flip cards met de FDND API, en dat werkte. Ik heb geleerd hoe perspective en rotateY werken in CSS, hoe je een dark/light mode bouwt met custom properties, en hoe je API-data in de DOM zet met insertAdjacentHTML. Hele kleine dingen die ik nu gewoon kan.

Browser Tech

Bij Browser Tech was het project een invulformulier voor de belansting dienst in de ns huisstijl. dat klinkt heel saai maar ik vond het eigenlijk superleuk. Vooral omdat ik de huisstijl van NS wel een leuke vibe vindt hebben. Bij dit vak had ik eigenlijk al gelijk een idee wat ik wilde maken. Ik wilde een formulier maken dat echt fijn in gebruik was, met veel kleine details die het verschil maken. Vooral met de progressive disclosure waar ik op het focussen was zodat het gevoel van de gebruiker verbeterd wordt bij het invullen van zo'n formulier. vragen werden verborgen totdat ze relevant zijn dus als iemand op ja klikte. Ook was ik bezig geweest met een input masking voor een IBAN-veld, validatie met user-invalid en user-valid in CSS zonder JavaScript, een datepicker die geen datums in de toekomst toelaat. Al die kleine dingen samen maken een formulier dat goed aanvoelt voor de gebruiker.

CSS to the rescue

Bij CSS to the rescue had ik het er nog wel moeilijk mee. Ik had veel gemist waardoor ik dit vak niet heb kunnen halen. Maar ik heb het vak naast de meesterproef zelf nog gevolgd om toch iets te maken waar ik trots op ben.

Ik ben begonnen met de silly walk opdracht maar ben daar helemaal van afgestapt. Ik wilde iets maken wat echt bij mij past. Mijn inspiratie zit altijd bij Apple, clean en strak design. Dus ben ik een Apple TV control panel gaan nabouwen. Een remote die je echt kunt bedienen, inclusief de bijbehorende interface. Alles in pure CSS, geen JavaScript.

Wat ik uit dit vak heb gehaald: het gebruiken van selectors zoals >, ~, & en @layer, keyframes voor animaties en hoe :checked werkt om interactie te bouwen zonder JavaScript. Dat laatste vond ik eigenlijk wel fijn, want JavaScript is niet mijn favoriete ding. Het project liet me zien dat je met alleen CSS meer kunt bouwen dan ik dacht.

Hackathon Nebula

Bij de Hackathon was het leuk. We werkte samen met een groepje van 4. Wat wel jammer was aan het samen werken was dat er gewoon geen structuur was. Ik probeerde elke keer structuur te krijgen. Maar mijn groepje ging veel door elkaar heen waaardoor het overzicht even kwijt was. De ervaring van de Hackathon was niet erg leuk ervaren. Ik merkte ook persoonlijk dat ik veel struggels heb gehad met het samen werken in git branches. Ik liep er gewoon elke keer vast. Dat is iets wat ik beter wil doen in de meesterproef vakken.

Human Centered Design

Bij HCD werkte ik met Ihab, die blind is en een screenreader gebruikt. Dit vak heeft me het meest verrast, omdat het me dwong om te ontwerpen voor iemand anders dan mezelf. In elke testsessie bleek ik het mis te hebben en ging het vaak niet goed. Maar ook zo kwam ik er achter wat ik wil en niet moet doen. Sneltoetsen die logisch leken werkten niet als de focus in een tekstveld zat. De screenreader praatte door mijn interface heen op momenten dat ik dat niet verwachtte. Focus management is iets waar ik nooit over had nagedacht, maar later uiteindelijk wel. Ook ove de aria-hidden niet betekent dat iets onzichtbaar is voor de gebruiker maar dat het betekent dat de screenreader het overslaat, maar dan mag je er ook niet doorheen tappen. Een fout die logisch lijkt maar grote gevolgen heeft gehad. Later pas kop niveaus heeft toegevoegd waardoor het strucuur van de pagina verbeterd werd.

Meesterproef / TAVI

Voor de meesterproef werkte ik in een groepje aan TAVI, een toegankelijkheidswebsite voor Gemeente Amsterdam. Het doel: mensen met een beperking helpen om door de stad te navigeren. Ik was de frontend designer van het team.

We bouwden een atlas met locaties door Amsterdam, die per plek laat zien hoe toegankelijk die is. Dat sloot mooi aan bij wat ik eerder had geleerd bij Human Centered Design — ontwerpen voor mensen met een beperking is geen bijzaak maar het vertrekpunt.

Ik ben vooral trots op het design dat ik heb neergezet. Het voelt als een project waar alles samenkomt: een echte opdrachtgever, een maatschappelijk doel en ruimte om mijn eigen designkeuzes te maken. Dat het voor Gemeente Amsterdam is maakt het extra betekenisvol.

API

Bij API heb ik gewerkt aan iets wat ik al vanaf dag één wilde, een Spotify integratie. Een swipe-interface waarmee je snel nummers uit een playlist kunt verwijderen of houden. Het was technisch het moeilijkste project van de minor. Astro was nieuw, de OAuth-flow van Spotify is complex, en zodra ik de app live zette op Render gedroeg alles zich anders dan lokaal. Ik heb deprecated documentatie gebruikt omdat de nieuwe niet werkten maar dat voelde niet ideaal, maar het was wel de pragmatische keuze. Wat ik ook eerlijk opschrijf: ik heb tijdens dit project soms Claude gebruikt, met name in de vakantie en bij de Render-bugs. Dat staat ook in mijn README. Ik heb het bewust gedaan en ik weet waar die code vandaan komt.

Weekly Nerds — Gastcolleges

Gedurende de minor hebben we wekelijks gastcolleges gevolgd van professionals uit het werkveld. Van toegankelijkheid en privacy tot creatief coderen en design systems — elk college gaf een andere inkijk in hoe het vak er in de praktijk uitziet. Wat me het meest is bijgebleven: dat het beroep veel breder is dan alleen code schrijven, en dat kleine keuzes in wat je bouwt grote gevolgen kunnen hebben voor de gebruiker.
